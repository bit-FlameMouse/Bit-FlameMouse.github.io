# 用飞书写笔记，怎么放进这个网站

结论先讲：**不建议把飞书文档直接嵌进网页，建议"导出 Markdown 放进仓库"或"放一个跳转链接"。**
下面是原因和具体做法。

---

## 先说结论：飞书文档为什么不适合直接嵌入

我查过飞书开放平台的官方文档（"网页组件概述"），它的云文档嵌入能力是这样的：

- 官方方案叫 **网页组件（Web Component）**，需要**在开发者后台创建自建应用、申请云文档权限、引入 SDK、做鉴权**；
- 鉴权需要 **服务端参与**（用 refresh_token 换签名，或应用身份授权），因为要保管密钥；
- 官方明确写了"网页组件只适用于**自建应用**"，定位是**企业内部系统**；
- 而且它要求给组件设置**固定高度**，否则文档里的图片、按需加载、虚拟滚动都会失效。

翻译成大白话：**这是给企业系统做深度集成用的，不是给个人静态网站用的。**
我这个站是零服务端、零构建的静态站点，用不了这套方案。

那"直接把飞书分享链接塞进 iframe"行不行？大概率不行，原因有三个：

1. **平台通常会拒绝被嵌入。** 响应头里的 `X-Frame-Options` 或 `Content-Security-Policy: frame-ancestors` 会拦住 iframe，浏览器显示"拒绝连接"。
2. **就算能加载，读者往往要登录。** 飞书文档的可见性依赖登录态，匿名访客看到的可能是登录页或权限提示——对"作品集"来说这是最差的结果。
3. **你控制不了它。** 飞书改一次策略、改一次域名，你的页面就白了一块。

所以我的建议是下面三种方案，按推荐度排序。

---

## 方案一：导出 Markdown 放进仓库（最推荐）

**优点**：和现有的项目文档完全一致；站内可搜索；不依赖飞书登录；不依赖第三方可用性；十年后还能读。
**缺点**：飞书里改了笔记，需要重新导出一次。

### 操作步骤

1. 在飞书打开笔记 → 右上角 `···` → **下载** → 选择 **Markdown**（没有的话选 Word/PDF 也行，但 Markdown 最省事）。
   飞书一般会给你一个 zip，里面是 `.md` 文件和图片文件夹。
2. 把 Markdown 放进 `content/docs/`，命名建议带上前缀方便识别：

   ```text
   content/docs/doc-feishu-my-note.md
   ```

3. 把导出附带的图片放进 `public/img/notes/<笔记名>/`，然后把 Markdown 里的图片路径改成相对路径：

   ```markdown
   ![示意图](../../public/img/notes/my-note/image-1.png)
   ```

   > 图片路径按 **Markdown 文件所在目录** 解析，由 `src/utils/paths.js` 统一处理，
   > 所以部署在 GitHub Pages 子路径下也不会 404。

4. 在 `src/data/content.js` 的 `docs` 数组里登记，并把飞书原文链接一起写上：

   ```javascript
   {
     id: 'doc-feishu-my-note',
     title: '我的笔记标题',
     description: '一句摘要，显示在卡片上。',
     category: '技术笔记',
     updated: '2025-02',
     body: 'content/docs/doc-feishu-my-note.md',
     url: 'https://xxx.feishu.cn/docx/xxxxxxxx',   // 可选：给出"查看原文"
   }
   ```

5. 跑一次校验并本地预览：

   ```bash
   npm run verify
   npm run dev
   ```

这样笔记会在站内核渲染，页面顶部会多出一个 **查看原文** 按钮，读者想评论或看最新版可以跳去飞书。

### 导出时的几个小坑

- **图片是本地文件还是链接**：飞书导出有时保留 CDN 图片链接。这种链接是**带签名和时效**的，过一段时间会失效，建议一律下载到 `public/img/notes/` 再引用。
- **表格与自定义块**：飞书的"多维表格""看板""思维笔记"导出后往往变成图片或直接丢内容，这类笔记建议**用方案二给链接**，别硬导出。
- **标题层级**：导出的 Markdown 如果首个标题是 `##`，站内目录（TOC）会从二级开始缩进，可以在文件开头补一个 `# 标题`。
- **代码块语言**：检查一下代码块是否带了语言标注（如 ```ts```），没有的话手动补，页面上会显示语言标签和复制按钮。

## 方案二：只放一个跳转链接（最省事）

**优点**：改飞书内容不需要动网站；适合频繁更新或飞书特有的块类型。
**缺点**：读者要跳出站点，而且需要飞书登录才能看。

在 `content.js` 的 `docs` 里**只写 `url`，不写 `body`** 即可：

```javascript
{
  id: 'doc-feishu-daily',
  title: '我的学习笔记（飞书）',
  description: '记录在飞书云文档里，点开跳转原文。',
  category: '技术笔记',
  updated: '2025-02',
  url: 'https://xxx.feishu.cn/docx/xxxxxxxx',
}
```

渲染效果：

- 卡片右上角会显示 **原文** 标记，按钮文案变成"前往原文"；
- 点击直接在新窗口打开飞书，不会进入站内阅读页；
- 侧边栏里同样会带 `· 原文` 后缀。

**记得把飞书文档的分享权限设成"互联网上获得链接的人可阅读"**，否则读者点进去会看到权限申请页。

## 方案三：尝试站内预览嵌入（了解即可，谨慎使用）

我实现了一个"点击后加载"的预览容器。在 `content.js` 里给带 `url` 的笔记加上 `embed: true`：

```javascript
{
  id: 'doc-feishu-my-note',
  title: '我的笔记标题',
  description: '尝试在站内预览原文。',
  category: '技术笔记',
  updated: '2025-02',
  url: 'https://xxx.feishu.cn/docx/xxxxxxxx',
  embed: true,      // ← 打开预览嵌入
}
```

行为是这样的：

- 页面先显示一个**占位面板**和"尝试加载预览"按钮，**不点击就不会请求飞书**（不影响首屏性能，也不把你的访问者信息提前送给第三方）；
- 点击后才创建 iframe，高度固定，占位显示"正在加载预览…"；
- 如果飞书拒绝嵌入，读者会看到空白或飞书自己的提示，但面板下方始终保留 **在新窗口打开** 的出口。

**再次提醒**：这一条大概率不会成功，它的价值是"如果你用的是允许嵌入的平台（比如某些公开的 Notion 页面、或者你自己的静态站点），可以直接用"。别把主内容押在它上面。

## 我的实际建议

| 笔记类型 | 建议 |
| --- | --- |
| 技术沉淀、想长期留在站内、会被引用 | **方案一**：导出 Markdown 入仓 |
| 频繁更新、或包含飞书特有块（多维表格、思维笔记） | **方案二**：只放链接 |
| 已经公开在允许嵌入的平台 | 方案三可用 |

混合着用也完全没问题——`docs` 数组里三种形态可以共存，卡片和详情页会自动适配。

## 常见问题

**改飞书内容后网站会同步吗？**
方案一不会（需要重新导出），方案二会（链接指向的始终是最新版）。这是两者最核心的取舍。

**能不能写个脚本自动把飞书导出的 zip 转成站点格式？**
可以，用 Node 解压 zip、把图片搬到 `public/img/notes/`、重写 Markdown 里的图片路径即可。但飞书导出格式不保证稳定，我倾向于先手动做几次，等确定格式稳定了再自动化——真要做，放在 `scripts/` 下和现有的 serve/verify 并列。

**`npm run verify` 会因为飞书链接报错吗？**
不会。校验只检查站内 `body` 指向的 Markdown 文件是否存在，外部链接不参与检查。但**如果同时写了 `body` 和 `url`，`body` 必须真实存在**，否则脚本会报"content.js 登记的 Markdown 不存在"。
